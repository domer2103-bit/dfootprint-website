# Coding Principles

> **Layer:** Delivery | **Purpose:** Standards for any code/automation work | **Status:** Active — source of truth | **Owner:** Founder | **Version:** 1.0

## Simple Architecture

Favour the simplest solution that works. Avoid over-engineering, unnecessary abstraction layers, or building for hypothetical future needs before they're real.

## Reusable Components

Build blocks (workflows, scripts, functions) so they can be reused across projects rather than rewritten each time. Think in terms of a personal toolkit that grows over time.

## Strong Documentation

Every project, workflow, or script should be documented well enough that it can be understood later without relying on memory — what it does, how it's set up, and how to change it.

## Avoid Unnecessary Dependencies

Don't add tools, libraries, or platforms unless they clearly earn their place. Fewer moving parts means fewer things that can break, and less to maintain.

## Readability Over Cleverness

Code and workflows should be easy to read and follow, even months later or by someone else. Clever, compressed, or overly technical solutions are avoided in favour of clear, obvious ones — same philosophy as the writing style: if it can't be explained simply, it's not understood well enough yet.
